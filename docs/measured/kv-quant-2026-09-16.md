  fp16 (448 -> 238, 896 -> 476, 4096 -> 2176 ...), q4_0 = 4.5/16. The card
  delta moves by the same amount, so nothing else grows to eat the saving.
- **What it buys, in the currency §24 cares about (window per MiB):**
  - 7B: **32K at q8_0 = 5 803 MiB vs 16K shipped = 5 731** (+72 MiB).
    Doubling the window costs what 16K costs today. 16K at q8_0 saves
    420 MiB; at q4_0, 644.
  - 32B: 32K at q8_0 = 23 603 vs 16K shipped = 23 329 (+274). 16K at
    q8_0 saves 1 915 MiB.
  - On the 7B the whole KV at 16K is only 896 MiB, so the "roughly halves
    what a window costs" in §13b is true in ratio and small in MiB at 16K;
    it matters once the window grows.
- **Speed:** generation -4 % (7B 255 -> 245 t/s; 32B 69 -> 66), prompt
  processing -0 to -7 %, flat across window. q4_0 is no slower than q8_0.
- **Flash attention is NOT a separate lever on this build.** The shipped
  argv already runs it (`-fa` defaults to auto, resolved "enabled"); a
  quantized V cache forces it on regardless. §13b's "--flash-attn with
  --cache-type-k" pair is one flag pair now, and `--flash-attn` takes a
  VALUE on this build (on|off|auto), so a bare `-fa` from older docs would
  swallow the next argument.
- **Not measured here: accuracy.** q8_0/q4_0 are lossy; the gate is the
  paraphrase matrix (§13b), filed as NEXT UP 11b.
- Also seen: `n_parallel` is auto = 4 slots on a unified KV, and `-fit`
  (on by default) reported "no changes needed" on every row. On a card
  where the load does not fit, `-fit` may shrink params silently; the
  probe's `fitChanged` column would show it.
